# Records requests

## Scope and mode
Operate for owners/admins; Read for visitors. Extend CivicPulse's existing resource directory and editor patterns.

## Audience and task
Residents follow requests; admins create them; assigned owners maintain a dated account, evidence and outcomes. Ownership identities/history stay private. Public, unlisted and private use runtime access checks.

## Direction
Use the incumbent Unna headings, DM Sans controls, cream background and green actions. A readable request summary leads into a chronological activity log; editing lives in clearly named disclosures.

## First viewport
Title, stage, outcome and organization relationships establish the request's current state. A clear manage action exposes the editor only to authorized users.

## Signature interaction
Posting a dated update records the back-and-forth independently of stage. Transfers show a private, append-only chain. Native disclosure motion only; no entrance animation.

## Supporting information and feedback
Fees show separate estimated, billed and paid USD totals with dated ledger entries. They are not combined into one cost total. Files and related coverage sit beside the timeline on wide screens and follow it on narrow screens.

Each editor form provides inline saving, success and error feedback through a polite live region. The directory and detail shell retain their loading and error status messages. Use the incumbent form, button and feedback styles.

Publishing shares request details, timeline, fees and links; account ownership and transfer history remain private. Individual files may remain private on a public request, and new uploads default private. Visibility and transfer controls explain these consequences where the user acts.

## Constraints and unresolved decisions
Static Astro shells, browser Supabase RPCs, private Storage, no automatic legal deadline calculations. Admin-only creation confirmed; per-file privacy confirmed, uploads default private. Code-led incumbent extension; no concept seed required.
