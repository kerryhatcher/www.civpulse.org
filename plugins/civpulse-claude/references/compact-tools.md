# Compact Civic Pulse MCP tools

Generated by `bun run plugin:build`. The opt-in endpoint is `https://api.civpulse.org/functions/v1/mcp/v2` after deploying this source. It exposes 79 tools; the existing connection and endpoint retain 128. All OAuth, visibility and admin checks are unchanged.

Use `search_site` with type/limit/offset for unified search (including past events). To preserve the old people, organization, map, election or event directory response/order, select `mode: "directory"` and the singular type. Event directory mode accepts organization_id, calendar_id and include_past (default false). Directory mode has no offset. Person/organization directory limits are capped at 50; other directories at 100. Defaults remain 20 for people/organizations/maps and 50 for elections/events.

Replace each main civic `get_<type>` with `get_civic_record(type, id)`. Responses, including enriched maps/people/elections/events, are preserved. Use `read_related_records` with `request.relation` and the original UUID keys. It replaces these original reads: get_map_layers → map_layers; get_person_articles → person_articles; get_organization_articles → organization_articles; get_person_candidacies → person_candidacies; list_person_organizations → person_organizations; list_contests → election_contests; list_ballot_questions → election_ballot_questions; list_contest_candidates → contest_candidates; get_contest_candidate → contest_candidate; list_map_layer_links → map_layer_links; get_organization_relationships → organization_relationships; list_article_people → article_people; list_article_organizations → article_organizations; list_calendars → calendars; get_office_terms → office_terms. Responses preserve their original arrays/status envelopes and ordering. The singular contest_candidate needs both contest_id and person_id. office_terms needs person_id or organization_id (both accepted). calendars keeps optional/nullable organization_id and the original unfiltered listing. map_layer_links, article_people and article_organizations remain admin-only; public person/organization article reading lists are separate selectors. All other original parent visibility and discovery checks remain in force. Unknown selectors, cross-selector keys and unsupported filters/pagination are rejected. Example: `{"name":"read_related_records","arguments":{"request":{"relation":"person_articles","person_id":"<person-uuid>"}}}`.

Specialized vote/legislative history, meeting/document reads, office directory, stored features/geometry, imports, uploads, publications and account tools retain their existing schemas.

Create/update pairs become `save_<resource>` for organization, calendar, event, person, election, map, layer, contest, ballot_question, article, layer_feature, office and office_term. Supply `request` with `operation: "create"` or `"update"` and all original fields/IDs. Branch schemas are strict: unknown fields, wrong IDs, missing required create fields and operation=delete are rejected. Updates never upsert; omitted fields are preserved, null clears supported nullable fields, and empty updates fail. Example: `{"name":"save_person","arguments":{"request":{"operation":"update","id":"<person-uuid>","phone":null}}}`.

Use `save_relationship` for map_layer, contest_candidate, person_organization, organization_relationship, person_relationship, article_person and article_organization. Supply `request.relationship` and `request.change` with operation and the original fields. Composite links require both endpoint UUIDs; organization_relationship and person_relationship updates use their row UUID and retain the original endpoint/label editing rules. Example: `{"name":"save_relationship","arguments":{"request":{"relationship":"map_layer","change":{"operation":"update","map_id":"<map-uuid>","layer_id":"<layer-uuid>","visible_by_default":false}}}}`.

Delete links separately with `delete_relationship`: `request` contains relationship and original key fields (both endpoint IDs for composite links; row id for organization_relationship and person_relationship). It preserves endpoint records. Resource deletes keep their existing separate tools; no office/office-term delete is added. `save_article` retains atomic metadata/association replacement: omitted sets stay unchanged and explicit [] still clears a set. `save_layer` edits metadata; dataset replacement remains `save_postgis_layer`. All writes retain the original admin-guarded handlers and RLS. Mixed save tools do not claim idempotency; reconcile uncertain creates before retrying. Reconnect to the original /mcp endpoint to roll back. Refresh the client tool catalog after changing endpoints.
